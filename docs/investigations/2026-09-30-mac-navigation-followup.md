# macOS navigation follow-up

Date: 2026-09-30

## Reproduction and change

During active playback, repeat Home → Search → Albums → Songs → Artists → Songs
twice through the sidebar. Instruments reproduced long main-thread intervals in
the signed, optimized build, without accessibility-tree snapshots during the
recording. Journey logs confirm all twelve transitions. Playback timeline reports
continued advancing.

`MacNativeTrackTableView.Coordinator` used one hidden `NSHostingView` to measure
both its header and footer. Each footer measurement replaced the header's SwiftUI
tree, and the next header measurement rebuilt it. The coordinator now retains
one sizing view for each role, using the same sizing helper. Dynamic and narrow
header measurement also share one path instead of duplicating it. Width caches,
forced content measurements, and the deterministic wide detail header remain.

## Instruments evidence

Time Profiler plus Activity Monitor attached to verified PIDs on Mac UUID
`E3A3882D-C3B6-5B96-805E-B89E87E9E955`, macOS 27.0.1 (26A434), Instruments 27.0.
Both conditions are signed Release builds using the same sandbox and library.
The frozen baseline is from `845aff79`. Source and executable hashes, PID,
recording duration, and per-transition results are in
[metrics.json](artifacts/2026-09-30-mac-navigation-followup/metrics.json).

The complete comparisons alternated baseline/candidate/baseline/candidate. The
first baseline recording lasted 46.2 seconds; the other three lasted 60.9–61.4
seconds. Compare the matching transitions rather than capture-wide totals. All
twelve actions and their resulting flagged intervals fit inside each accepted
recording. The second comparison restarted the same track before each run.
Animations remained enabled. No compiler or package tests ran during recording.

For the four returns to Songs in each run:

| Condition | Sampled sizing work within those intervals, total | Mean flagged interval |
| --- | ---: | ---: |
| Baseline first | 614 ms | 751.6 ms |
| Candidate first | 192 ms | 424.4 ms |
| Baseline repeat | 534 ms | 663.9 ms |
| Candidate repeat | 199 ms | 509.6 ms |

Across eight matched returns per condition, sampled sizing work averaged
143.5 → 48.9 ms (66% lower), and the flagged interval averaged
707.7 → 467.0 ms (34% shorter). These are observed results from two captures per
condition on one Mac, rather than a general latency guarantee. The sizing helper
includes footer sizing; its sampled time is not an independent total CPU metric.

Navigation still stalls. Total hang flags were 12/10/12/12 across the accepted
runs. Other stacks include native split-view replacement, SwiftUI/AppKit layout,
and accessibility work generated by the system/input path. Tree snapshots were
excluded, but accessibility overhead was not eliminated completely.

The complete sixty-second captures showed peak footprints of 564 MiB for the
repeated baseline and 477/548 MiB for the candidates. Their variation does not
establish a memory improvement or absence of leaks. One CoreAudio overload log
occurred near the repeated baseline's recording start, before its first sidebar
action; no navigation/audio causality is established by that event.

## Pre-existing Core test failures

All three failures reproduced before editing the tests (15 failed assertions).
The two remote library cleanup tests inherited persisted local flag timestamps
from other tests/runs. Their untimestamped legacy payloads were correctly
rejected by `AccountManager` before cleanup began. The cleanup test class now
saves, clears, and restores just that defaults key around each test. Production
sync ordering and deletion protections are unchanged.

The case-insensitive merged-playlist permalink test expected the first inserted
title spelling, despite repository ordering by newest update for equal titles.
It now supplies the source preference that makes that spelling authoritative.
Merged detail lookup already normalizes titles; no production routing change was
needed.

The three affected classes passed all 64 tests, including stale remote-flag
rejection. The complete Core run then passed 1,195 XCTest tests and eight Swift
Testing tests with no failures. Logs: `failure-fixtures-isolated.log` and
`core-full-isolated-fixtures.log` in the run directory below.
