- Every async command runs through `runOperation` (AMC:931-958), which takes a new operation generation (AMC:937), registers cancellation of the previous one (AMC:939, AMC:228-238), and returns `staleResult` silently when superseded (AMC:947-950). **Identity carried by events.** `queueGeneration` is `activeQueueGeneration`, set to the operation generation of the `play` or `startStation` that built the queue (AMC:564, AMC:868) and nilled by `stop`, a pause during preparation, preparation start, and preparation failure (AMC:784, AMC:748, AMC:965, AMC:984). The service accepts a callback only if it equals the controller's current value, Apple Music is enabled, the current track is Apple Music, and the state is loading/buffering/playing (PS:484-501, PS:6449-6462). Two consequences for the reducer design:
- This is a per-queue identity, not per-item. In a station one generation spans every track.
- It is a different number space from `playbackGenerationCounter`, which guards the native engine (PS:1140, PS:1389, PS:1409, PS:1509). Apple callbacks are never compared with `playbackGenerationCounter`; they rely on `stop()` having nilled the controller generation.

**How each condition is detected.**
- Progress: polled, 4 Hz, never pushed by MusicKit (AMC:429, AMC:486). No samples while paused or stopped (AMC:459).
- Natural completion: inferred, four ways, de-duplicated by `hasReportedEnd` (AMC:1271):
  1. time within 0.05 s of duration on a final entry (AMC:500-503, AMC:58-64);
  2. two consecutive stationary samples within 0.25 s of the end (AMC:504-508, AMC:66-72, AMC:164-186);
  3. player not playing, time under 0.5 s, and the last playing sample was on a final entry (AMC:460-468, AMC:119-130);
  4. state went paused/stopped, still so after 300 ms, and the position or last snapshot is within 0.5 s of the end or has reset to the start (AMC:1178-1183, AMC:1216-1218, AMC:1230-1268).
  "Final entry" means no station, no MusicKit successor, and Repeat One off (AMC:49-56). With a one-item queue, trigger 3 is also what an external Next press looks like, so an external Next is reported as natural completion.
- External pause: paused/stopped state that survives 300 ms and is not at the end boundary (AMC:1219-1226). Suppressed while an interruption is active and until playback resumes (AMC:795-802, AMC:1214-1215).
- External play: state becomes `.playing` while `wasPlaying` is false and no end was reported (AMC:1184-1193).
- External Previous: not an event. The service infers it from a rewind in the time stream (PS:6417-6433, PS:276-285); see section 5.
- Errors: no error callback exists. Failures surface only as a thrown error from an in-flight command; a mid-track failure appears as an unexpected pause or not at all.
- Stall / buffering: not surfaced. The service sets `.buffering` itself around resume (PS:3256).

**Observation and timers.**
- `player.queue.objectWillChange` and `player.state.objectWillChange`, each with `receive(on: main)` plus an extra `DispatchQueue.main.async` hop so the handler reads the post-change value (AMC:1286-1298).
- Permanent 250 ms poll started in `init`, runs for the controller's lifetime, early-returns without an active generation (AMC:426-440).
- 300 ms end-confirmation task (AMC:1202-1204).
- Background heartbeat log every 10 s when the app is not active (AMC:444-457).

## 4. MusicKit queue model

| Contract | Where implemented |
|---|---|
| Finite queue is one item long | `PlaybackService.appleMusicSegment` returns `[first]` (PS:448-451), used at PS:6194. The controller itself accepts any array (`Queue(for: songs, startingAt: first)`, AMC:569); the limit is enforced only by the caller |
| Finite queue is disposable | Every start calls `controller.stop()` (PS:6211) and then `beginQueuePreparation`, which stops the player and empties entries (AMC:541, AMC:960-976) before building a new `Queue` (AMC:569). `stop()` empties entries (AMC:785-786). A logical queue mutation discards MusicKit successors or stops and rebuilds (PS:4184-4200) |
| Three-second Previous threshold | Constant PS:273. Shared policy QP:25-41 (`currentTime > restartThreshold` → restart), called from `previous()` PS:3689-3694. Also used by the Apple rewind inference PS:282, PS:6417, PS:6420. A separate hard-coded `currentTime > 3` decides remote Previous availability (PS:7009) |

Because the segment is always one track, the multi-item machinery in the controller is unreachable for finite playback today: `resolveSongs` either resolves the first track or throws (AMC:20-27, AMC:705-717), so `unresolvedPlaybackIdentities` is always empty and the queue pruning at PS:6228-6238 never removes anything; `hasQueuedSuccessor` (AMC:403-410) is true only inside a station.

The one exception to "one item, disposable" is the autoplay **station**: `Queue(for: [station])` (AMC:869), where MusicKit owns order and advance and the logical queue mirrors it (PS:6342-6398).

Other MusicKit-specific constraints in code:
- Platform: `#if os(iOS)` (AMC:326, PS:1128) and `@available(iOS 18, *)` (AMC:374, PS:4733, PS:6117). On iOS 17, macOS and watchOS an Apple Music item falls into the native path, where `AppleMusicSourceProvider.getStreamURL` throws `musicKitPlaybackRequired` (`AppleMusicSourceProvider.swift:682-689`).
- Singleton player `ApplicationMusicPlayer.shared` (AMC:377).
- No authorization or subscription check on the playback path. `MusicAuthorization`/`MusicSubscription` are consulted only at source setup (`Packages/EnsembleUI/Sources/Screens/AccountSettings/AddSourceView.swift:138-148`). Playback gates on `accountManager.isAppleMusicEnabled` only (PS:493, PS:4518). A lapsed subscription surfaces as a thrown MusicKit error turned into `.failed(error.localizedDescription)` (PS:6249-6255).
- Catalogue resolution: batches of 25 (AMC:619), per-ID retry when a batch fails (AMC:639-653), library fallback when the catalogue ID did not resolve (AMC:39-46, AMC:657-683), title/artist/duration ±1 s matching as a last resort for identifying the current entry (AMC:133-158). A lookup error on the first track is rethrown (AMC:710-715); a definite miss throws `musicKitPlaybackRequired` (AMC:716).
- Repeat: only `.one` or `.none` is ever written to MusicKit (AMC:567, AMC:807, AMC:867). Repeat All stays in the service.
- Transition: `.none` for finite queues (AMC:565); `.crossfade` for a station when Smart Mix is on (AMC:865).
- Station start: requires a catalogue ID and a `station` relationship (AMC:845-857); sequence is `prepareToPlay` → `skipToNextEntry` → `play` (AMC:194-206).
- Audio session: `.playback` with `.mixWithOthers` while MusicKit is the owner (PS:4735, PS:3269), restored to non-mixable `.longFormAudio` before the native engine loads (PS:5737-5754, `PlaybackAudioSessionCoordinator.swift:84-96`).
- Interruptions and route changes: "MusicKit owns" them; the service returns early and never feeds `PlaybackHandoffCoordinator` (PS:2415-2425, PS:2461-2473).
- Background: completion depends on the poll running. A background task is held for the last 4 s of a final Apple entry (PS:453-469, PS:6438-6444, PS:1997-2013) and across the start (PS:4725, PS:4745).
- No waveform, visualizer, prefetch or pre-buffer for Apple items (PS:1855, PS:6198-6202, PS:5442-5447, PS:5986, PSC:105-107, PS:6511).
- Entries may be transient: `resolvedOrTransientSong` (AMC:1281-1284).

**Progress generation check (second review finding).** Both paths now check a generation, so "only one path generation-checks progress" is no longer accurate, but they check different things:
- Native: `progress.generation == playbackGenerationCounter`, `engine.isCurrentProgress`, track identity, and only while `.playing` (PS:1506-1519).
- Apple: controller queue generation, Apple enabled, current track is Apple, state loading/buffering/playing; no per-item identity (PS:6406, PS:484-501).
Both now feed the 15 s progress checkpoint (PS:1529, PS:6436). Only the native path calls reporting (PS:1534).

## 6. `PlaybackQueueController` and `PlaybackQueueStore`

**Ownership.**
- `PlaybackQueueController` owns no queue. Its only state is the legacy auto-generated ID set (PQC:31, PQC:499-523). Every mutation takes the service's arrays `inout`.
- `PlaybackService` owns: `queue` (PS:836), `currentQueueIndex` (PS:839), `originalQueue` (PS:1122), `playbackHistory` (PS:1133), `hasUserQueueEdits` (PS:843), `isShuffleEnabled` (PS:844), `repeatMode` (PS:847), `isAutoplayEnabled` (PS:860), `autoplayTracks` (PS:869), `radioMode` (PS:871), `recommendationsExhausted` (PS:872), `queueStateRevision` (PS:842).
- `PlaybackQueueStore` owns the pending write (PQS:72-73).

**Persisted.**
- `PlaybackQueueSnapshot`: queue, history, currentIndex, currentTime, originalQueue, shuffleEnabled, hasUserQueueEdits (PQS:3-15), as JSON in Application Support `PlaybackQueueSnapshot.json` (PQS:93); position separately in `PlaybackQueueProgress.json` (PQS:95).
- Future autoplay items are stripped before saving (PQC:459-470, QP:127-145).
- Shuffle, repeat, autoplay and Smart Mix preferences are `UserDefaults` keys (PS:581-587). Repeat mode is not in the snapshot.
- History is persisted and restored (PS:7059, PS:7142); the comment at PS:1132 saying it is not is stale.

**When.**
- `savePlaybackState` (PS:7045-7066) after each mutation or advance; the store coalesces for 1 s (PQS:84, PQS:116-124).
- Position every 15 s of observed progress from either engine (PS:2148-2154, PS:7068-7078); written immediately when no snapshot is pending (PQS:127-135).
- `persistPlaybackStateSnapshot` flushes, gated on restoration having resolved (PS:7081-7088, PQS:137-142).
- An empty queue and history deletes both files (PQS:241-246).

**Shuffle order.** `queue` holds the shuffled order and `originalQueue` the unshuffled one; both are saved. Enabling puts the current item first, then shuffled candidates that are neither autoplay nor already in history, then autoplay (QP:100-115); already-played items therefore drop out of `queue` but stay in `originalQueue`. Disabling assigns `queue = originalQueue` and finds the current item by item ID (PQC:163-180). Insert and remove patch `originalQueue` while shuffled (PQC:200-211, PQC:233-237, PQC:251-253).

**Restoration** (`restorePlaybackState`, PS:7092-7227):
1. `startupCoordinator.beginRestoration` (PS:7093); load on a detached task (PS:7097-7099). A read error keeps the saved file and reports `.readFailed` (PS:7100-7105). Only a missing file falls back to legacy defaults (PQS:161-169).
2. Resolve a local download for the saved track (PS:7118-7125).
3. Prune items whose source is no longer configured (PS:7132-7135, PS:702-726).
4. Abort if a queue or playback already exists (PS:7138-7141).
5. Restore history, write back any repair (PS:7142-7143).
6. `makeRestoreDecision` prunes future autoplay and picks the pre-buffer mode (PSC:53-112); Apple Music gets `.none` (PSC:105-107).
7. Publish queue, original queue, index, shuffle flag (snapshot value wins over the preference, PSC:99, PS:7179-7183), queue protection, `.paused`, `pendingPreBufferTime` (PS:7184-7194).
8. Optional pre-buffer and autoplay refill (PS:7206-7224). Playback is never started, and nothing is donated.

**One live queue?** Yes for published state: one `queue` (PS:836). `originalQueue` is a private shadow. The controller's `submittedTracks` (AMC:384) and MusicKit's own queue are transport copies. The caveat is station mode, where MusicKit's queue is authoritative for upcoming items and overwrites the logical future (PS:6382-6384).

## 7. Handoff

### 7a. Between engines (inline in `PlaybackService`)

**Plex → Apple Music**
1. Native completion: `engine.onPlaybackComplete` (PS:1387) → `handleQueueExhausted` (PS:1739) → index advanced (PS:1819) → `playCurrentQueueItem` (PS:1820).
2. `playCurrentQueueItem` (PS:4701): bump `appleMusicQueueMutationGeneration` (PS:4708) and `playbackGenerationCounter` (PS:4719); begin background task (PS:4725).
3. Apple branch (PS:4733): `audioEngine?.stop()` (PS:4734); session to mixable (PS:4735); `playCurrentAppleMusicSegment` (PS:4741); end background task (PS:4745).
4. `playCurrentAppleMusicSegment` (PS:6182): one-item segment (PS:6194); publish track, time, `.loading` (PS:6199-6204); create controller if needed (PS:6207); `controller.stop()` (PS:6211); `controller.play` (PS:6219).
5. Controller `performPlay` (AMC:535): tear down (AMC:541), resolve (AMC:542), set maps and generation (AMC:557-564), set queue (AMC:569), `prepareToPlay` (AMC:573), set start time (AMC:576), `play` (AMC:577), mark playing (AMC:580-587).
6. Back in the service: generation and identity check (PS:6224-6227), prune (PS:6228-6238), `.playing` (PS:6239).

**Apple Music → Plex**
1. Controller reports end (AMC:1270) → `onEnded` (PS:6133) → `advanceAfterAppleMusicSegment` (PS:6289).
2. Accept check (PS:6290); next index (PS:6294); station check (PS:6303-6309); stop if none (PS:6310-6313); history, index, `.loading`, skip flag (PS:6314-6321); `playCurrentQueueItem` (PS:6322); save (PS:6323).
3. Non-Apple branch (PS:4748): `controller.stop()` (PS:4750); publish new track and `.loading` (PS:4756-4765); keep the session mixable for now (PS:4766-4768); prepare engine (PS:4782).
4. `loadAndPlaySource` (PS:5698): activate session (PS:5723); restore the non-mixable category, one retry after a yield (PS:5737-5754); `engine.load` (PS:5792).

**Apple Music → Apple Music**: steps 1-2 above, then the Apple branch of `playCurrentQueueItem`, so a full stop and rebuild.

**Failure modes guarded**
- Stale Apple callback after stop or replacement: PS:6449-6462.
- Superseded request after an await: PS:6224, PS:4789-4798, PS:5710, PS:5726, PS:5740.
- Late MusicKit completion after pause/stop: AMC:997-1009.
- Pause during preparation discards the half-built queue (AMC:747-753); resume then rebuilds (PS:3253-3265); a failed resume rebuilds (PS:3277-3284).
- Audio session failure: `.failed` (PS:4735-4740, PS:4766-4774, PS:5744-5753).
- Cancellation or error from MusicKit: both engines stopped, `.failed` (PS:6241-6256).
- App suspension at the boundary: end-transition lease (PS:6438-6444).
- Callbacks during a mutation-driven stop: `isSynchronizingAppleMusicQueueMutation` (PS:4192-4194, PS:6453).

Not guarded on the Apple completion path: `shouldSuppressAutomaticAdvance` is consulted for native completion (PS:1608, PS:1759) but not in `advanceAfterAppleMusicSegment`; it applies only later if the successor is native (PS:5780).

### 7b. `PlaybackHandoffCoordinator` (route / interruption / transport)

- State: `pauseReason` (user, disconnect, interruption, system), `routeTransition` (idle, disconnecting, settlingNewDevice), `interruption` (none, began, ended) (PHC:17-22, PHC:60-97).
- Inputs: PHC:35-45. Outputs: PHC:122-127, applied by `applyHandoffOutcome` (PS:2300-2335).
- Guards:
  - interruption arriving within 1 s of a disconnect is treated as a duplicate (PHC:137, PHC:328-335);
  - a play command clears a stale `.began` interruption so playback cannot deadlock (PHC:214-220);
  - buffering left over after a route settle window is resumed (PHC:307-315);
  - interruption ended without resume turns buffering into a stable pause (PHC:371-381);
  - automatic advance is suppressed during any of these (PHC:170-174);
  - remote skip is disabled while loading or buffering unless a skip is already in progress (PHC:176-185), plus a 0.3 s debounce in the service (PS:2397-2402).
- Apple Music bypass: interruption and route notifications return before reaching the coordinator when the current track is Apple Music (PS:2415-2425, PS:2461-2473). An externally detected Apple pause calls `applyPauseForHandoff(.system)` directly and does not set `pauseReason` (PS:6144).

## 8. Now Playing bridge and reporting

**Bridge reads**: a `PlaybackNowPlayingState` value built by the service (PS:6997-7037), pushed (PS:6990) or pulled through `currentState` (PS:2504, NPB:429, NPB:700).

**Bridge writes**
- `nowPlayingInfo` (NPB:354, NPB:405) and `playbackState` (NPB:406, NPB:723).
- Command `isEnabled`, `isActive`, `currentShuffleType`, `currentRepeatType` (NPB:304, NPB:309, NPB:439-456).
- Command targets (NPB:225-312).

**Other writers of system Now Playing**
- None in the iOS/macOS app code. `Ensemble/App/WatchCompanionBridge.swift:228` only reads.
- The Watch app writes its own on watchOS (`Packages/EnsembleWatchCore/Sources/EnsembleWatchCore.swift:836`, `:1029`, `:1040`, `:1046`, `:1080`; `EnsembleWatch/App/WatchSessionModel.swift:378-456`).
- Unverified from source: `ApplicationMusicPlayer` is a system player. The code infers external pause, play, Previous and Next from player state rather than receiving them through the bridge handlers (PS:6140-6156, PS:6423-6432, AMC:460-468), which suggests the system addresses MusicKit directly while it is the audio owner. Whether MusicKit also publishes Now Playing metadata alongside the bridge was not checked on a device.

**Writing playback state back**: the bridge never touches service state. It calls handler closures (NPB:128-142):
- play / pause / toggle → `resumeInternally` / `pauseInternally` with `.system` (PS:2508-2527);
- next / previous → `next()` / `previous()` after `shouldAcceptSkip` (NPB:243-253, PS:2385-2403, PS:2528-2533);
- seek → `seek(to:)`, with stale events rejected (NPB:255-284, NPB:563-573, PS:2534-2536);
- repeat / shuffle → `setRepeatMode` / `setShuffleEnabled` (PS:2537-2538);
- like / dislike → `toggleLike` (PS:2539-2540).
Remote commands do not pass through `play(tracks:context:)` and carry no origin.

**Reporting**
- Reads the track, time, duration and connectivity flag passed in (PRC:46, PRC:54-59).
- Writes Plex timeline state changes (PRC:46-52), a periodic "playing" report every 10 s backing off to 30 s and 60 s (PRC:64-83, PRC:106-114), and a scrobble at 90 % (PRC:85-104, PRC:116).
- Never writes playback state.
- Call sites: progress PS:1534 (native only); paused PS:2368; playing PS:3316, PS:3382; stopped PS:3414.
- Apple Music: no periodic call (PS:6402-6445). State reports are sent for any track, and the Apple provider's implementations are empty (`AppleMusicSourceProvider.swift:953-954`).
- `resetForTrack` is called only on gapless advance, Smart Mix promotion, and source pruning (PS:1643, PS:1688, PS:6853). No call was found on an ordinary track start through `playCurrentQueueItem`.

## 9. Donations

- Single donation site: `SystemMediaIntegrationService.donatePlaybackStart` (SMIS:390-421).
- Single filter: `guard origin == .appUI` (SMIS:395-398). Skipped entirely on macOS (SMIS:400-401).
- Origins: SMIS:11-20.
- Reached only from `play(tracks:startingAt:context:)` (PS:2803) and `shufflePlay(tracks:context:)` (PS:2950) through `donatePlaybackStartIfNeeded` (PS:2959-2973).

| Origin | How it is excluded |
|---|---|
| Siri | `origin: .siri` (SPC:299-317) fails the guard |
| App Shortcuts | Run through the same coordinator (`Ensemble/App/EnsembleAppShortcuts.swift:352`), so they are tagged `.siri`; `.appShortcut` is never constructed in production |
| Remote commands | Call `resume`/`next`/`previous` directly (PS:2508-2533); never reach a donation call. `.remoteCommand` is never constructed |
| Autoplay | `playCurrentQueueItem` directly (PS:1840, PS:3600) or a station (PS:4521) |
| Restoration | Never starts playback (PS:7192) |
| Recovery | `retryCurrentTrack` / `playCurrentQueueItem` (PS:1558, PS:3280, PS:6005) |

Structural exclusions that are not origin checks: `playQueueIndex` (PS:3129), `playFromHistory` (PS:3173) and `enableRadio` (PS:4543-4586) never donate.

Default risk: a caller that omits the context gets `.userInitiated`, which is `.appUI` (SMIS:75, PS:215-224, PS:2678-2691, PS:2842-2844). `Ensemble/App/WatchCompanionBridge.swift:336` and `:338` start playback this way on behalf of the Watch, so those starts are donated as app UI.

## 10. Proposed normalized `EngineEvent` (Apple Music engine)

```swift
enum EngineEvent: Sendable {
    case started                                   // async return of play/startStation/resume
    case itemChanged(EngineItem)                   // onTrackChanged + onDynamicTrack
    case progress(time: TimeInterval)              // onTimeChanged
    case paused                                    // onPaused (external only)
    case resumed                                   // onResumed (external only)
    case finished                                  // onEnded
    case upcomingChanged([Track])                  // onDynamicQueueChanged (station only)
    case metadataChanged(Track)                    // onTrackMetadataChanged
    case failed(EngineFailure)                     // thrown errors of commands
}

enum EngineItem: Sendable {
    case submitted(playbackIdentity: String)       // maps to a logical queue item
    case engineSupplied(Track)                     // station entry unknown to the queue
}
```

| Case | Replaces | Reliability from MusicKit |
|---|---|---|
| `started` | `playbackState = .playing` after the await (PS:6239, PS:3275), station success (PS:4526-4532) | Reliable; it is the command's own completion |
| `itemChanged` | AMC:1036, AMC:1045, AMC:1050 → PS:6261, PS:6342 | Reliable in the foreground; in the background it depends on the poll |
| `progress` | AMC:486 → PS:6402 | Polled at 4 Hz, only while playing; no seek or discontinuity marker, so rewinds are inferred |
| `paused` / `resumed` | AMC:1225, AMC:1192 → PS:6140, PS:6146 | **Not reliable**: delayed 300 ms, no reason (user, interruption, error, route), suppressed during interruptions |
| `finished` | AMC:1278 → PS:6133 | **Not reliable**: four heuristics, also fired by an external Next; can be missed if the app is suspended |
| `upcomingChanged` | AMC:1150 → PS:6377 | Station only; entries may be transient |
| `metadataChanged` | AMC:1115, AMC:1131 → PS:6328 | Best effort |
| `failed` | catch blocks PS:6241-6256, PS:3277, PS:3512, PS:4533 | **Only for command failures**; no mid-playback error source exists |

Cases the MusicKit player cannot supply and that should not be invented: stalled/buffering, external Previous or Next as distinct commands, a pause reason, and buffered progress.

Session tagging: the controller's operation generation (AMC:564, AMC:868) can stay private to the adapter. The adapter should stamp each event with the `SessionID` handed to it in the start effect, replacing both `isCurrentAppleMusicQueue` (PS:6449) and the `playbackGenerationCounter` checks around awaits (PS:6224).

## 11. Open questions

1. External Next on a finite Apple item is indistinguishable from natural completion (AMC:460-468). Should the reducer treat it as `next` (history, Repeat One advances) or as completion (Repeat One would replay)? Today it is completion.
2. External Previous within the first 3 s on a finite Apple item is not propagated unless a restart was already observed (PS:6420-6432). Is that the intended contract or an accepted limitation?
3. Station mode breaks "the reducer owns queue policy": MusicKit advances and reorders, and the logical queue mirrors it (PS:6342-6398). Does the plan model a station as an engine-owned continuation, or should the adapter keep stations one item long as well?
4. External Previous inside a station appears to append a duplicate autoplay item, because `handleAppleMusicRadioTrack` searches only forward (PS:6357-6366). Not reproduced; needs a device check.
5. Any queue mutation during a station (shuffle, Play Next, Play Last, reorder) stops the station and restarts the current track as a finite item (PS:4184-4200). Intended?
6. `shouldStartAppleMusicAutoplay(isWrappingQueue:)` is never passed in production (PS:6303). Dead parameter, or a missing argument?
7. `advanceAfterAppleMusicSegment` has no Repeat One branch and skips the native guards (PS:6289-6324 vs PS:1754-1813). With one policy, which guard set wins: rapid-advance limit, failed-state stay, interruption suppression?
8. The one-item contract is enforced only by `appleMusicSegment` (PS:448-451); the controller still carries multi-item resolution, pruning and successor logic (AMC:14-37, AMC:403-410, AMC:894-913, PS:503-520, PS:6228-6238). Remove with the restructure, or keep for a future multi-item queue?
9. Does `ApplicationMusicPlayer` publish its own Now Playing and receive remote commands while it is the owner? This decides whether "only the bridge writes Now Playing" can hold for Apple items. Needs the physical device.
10. `reportingController.resetForTrack()` has no call on an ordinary track start (PS:1643, PS:1688, PS:6853 are the only sites). If confirmed, scrobble and timeline gating carry over between non-gapless tracks. Out of scope here, but the reducer's reporting effect should define the reset point.
11. No authorization or subscription check on the playback path (section 4). Should the adapter surface a typed failure instead of a localized MusicKit string?
12. Watch-initiated starts are donated as app UI (`Ensemble/App/WatchCompanionBridge.swift:336-338`). Should they carry a non-donating origin?
13. `.appShortcut`, `.remoteCommand`, `.autoplay`, `.gaplessAdvance`, `.queueRestoration`, `.backgroundRecovery` are declared (SMIS:11-20) but never constructed. Keep as the reducer's command origins, or trim?
14. `moveItem` does not update `originalQueue` (PQC:279-322), so a reorder made while shuffled is lost when shuffle is turned off. Intended?
15. The Apple end monitor polls for the controller's lifetime (AMC:426-436). The 2026-09-04 review suggested stopping it when idle; still open.
