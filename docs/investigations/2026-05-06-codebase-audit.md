## Method

The original file index was generated by a static analyzer that recorded path, package/target, role, imports, major types, line count, migration markers, cleanup notes, test signal, project-skill alignment, general best-practice alignment, and risk level. The generated index snapshots are no longer tracked because they can drift quickly from current source.

## Migration Backlog

1. `EnsembleWatch/Views/WatchRootView.swift`: still the only critical finding. The known issue is accurate: watchOS auth cannot compile until the missing auth ViewModel/factory problem is resolved or the watch flow is redesigned.
2. `Packages/EnsemblePersistence/Sources/Repositories/PendingMutationRepository.swift`: `scripts/check_core_warning_budget.sh` fails because `CDPendingMutation.MutationType` is captured in a `@Sendable` closure without Sendable conformance. Tests pass, but the warning-budget gate is currently red.
3. API debug logging: `PlexAPIClient.swift`, its endpoint extensions, `ConnectionFailoverManager.swift`, and `PlexWebSocketManager.swift` contain most of the 211 logger calls inside `#if DEBUG`. The project skill explicitly says logger calls should not be compiled out unless the surrounding code itself is debug-only.
4. Streaming/download legacy paths: `PlexAPIClient+Playback.swift`, `PlaybackService.swift`, `PlaybackQueueStore.swift`, and `DownloadManager.swift` retain intentional legacy compatibility paths. These should be cleaned only with migration tests and rollback notes.
5. CoreData/domain migration: `ModelMappers.swift` still notes `Track.streamId` is not stored in CoreData and would require migration. This matters for waveform/loudness features if they need persistent stream IDs.
6. Deprecated local APIs: `QueueManager.moveQueueItem(from:to:)`, `PlaybackService.moveQueueItem(from:to:)`, and old artwork download wrappers are still present for compatibility. They should be removed only after call-site and persisted-state checks.
7. UI compatibility aliases: `AuxiliaryPresentationContainer`, `NavigationCoordinator.openSettings`, and iOS 15 navigation fallbacks are expected compatibility debt. Do not remove them during broad cleanup.

## Best-Practice Comparison

General Swift/Apple consensus is mostly being followed: type names are descriptive, packages keep a clear dependency direction, UI-facing state generally stays on the main actor or in SwiftUI-owned wrappers, and production logging uses `Logger` helpers rather than `print`.

The repo is intentionally stricter than generic guidance in several places:

- `os.Logger` calls should stay available in release/TestFlight builds for beta diagnostics.
- iOS 15/A9 devices require projection objects, local `@State`, and `CurrentValueSubject` for high-frequency values instead of broad `@ObservedObject` use.
- CoreData writes and download flows need more defensive nil/source handling than a typical greenfield app because the beta has real migration and cache-healing requirements.
- UI token/scaffold rules are stricter than generic SwiftUI style guidance because cross-platform density and iOS 15 compatibility matter more than local visual convenience.
- Plex streaming rules are project-specific and evidence-based; do not simplify playback by disabling universal transcode fallback without repeating endpoint tests.

Main best-practice gaps:

- Public API doc-comment coverage is inconsistent by static scan. This is partly noisy because many public declarations are properties, but large public service/model files should get doc-comment cleanup when touched.
- `Task.detached` appears 26 times. Most are plausible background work, but every future edit should re-check cancellation, priority, and actor isolation.
- `UserDefaults.didChangeNotification` appears only in `PlaybackService.swift`, and the comments indicate cache-and-compare guarding. Keep that pattern; do not add new broad defaults observers.
- `GeometryReader` usage is concentrated in UI layout surfaces. Existing usage may be valid measurement work, but any scroll/layout jank pass should include Artists, Albums, Playlists, and root/detail shells.
