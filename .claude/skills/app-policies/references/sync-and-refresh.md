# Sync And Refresh Policy

Load this reference for Feed/library freshness, stale-while-revalidate behavior, pull-to-refresh, background refresh, WebSocket-triggered sync, source cleanup, or Siri index/context refresh.

## Policies

- Feed and library surfaces are offline-first: show cached or last-good data immediately, then refresh in the background.
- Apple Music is an iOS/iPadOS 18+ device-local source. Its enablement stays in local `UserDefaults`; it must not enter KVS, CloudKit, Keychain source sync, or Watch library payloads. Its normalized library may enter the device-local Siri/App Intent shared index so phone requests resolve through the same source-scoped playback router. Apple Music API library inventory and native MusicKit library-playlist snapshots form one authoritative union; REST-only playlists and their paginated track relationships must remain visible without duplicating MusicKit matches. Every Apple API page retains the initial request's extensions and relationships so favorite state plus library artist/album/catalog identity remain available throughout the library; library-only song IDs stay distinct from catalog IDs and use MusicKit library playback rather than catalog requests. Each authoritative library inventory concurrently pages native `MusicLibraryRequest` values for songs, albums, and artists and joins them only through exact library item/relationship IDs. Native song metadata supplies library-added, last-played, and play-count values; native album and artist metadata supplies their exact library-added values, with the earliest exact child-song date used only when a synthetic group has no matching native collection date. Those provider-authoritative added dates replace earlier non-nil synthetic cached values after upgrade; Plex retains its fill-only merge semantics. Song, album, and artist modification dates remain unset because Apple exposes no corresponding documented field, and a failed native metadata inventory fails the authoritative phase without replacing last-good rows. Artist detail uses source-scoped cached Apple library albums and tracks when present and never supplements them with the artist's broader catalog discography. Apple exposes no documented modified-since library cursor, and `MPMediaLibrary.lastModifiedDate` reflects database persistence rather than a content revision. Routine incremental library sync therefore reuses a successful authoritative inventory for up to 24 hours. A missing baseline, regressed local clock, or the 24-hour reconciliation boundary requires the complete paginated inventory before orphan deletion; provider-owned in-app mutations reconcile their affected entities independently. Sync compares source-scoped normalized metadata before writing. Playlist inventory refreshes every header, while provider modification dates let full and incremental sync reuse unchanged cached bodies. When a body is fetched, compare its normalized header plus ordered membership identity and fallback snapshot metadata with `PlaylistSyncState`; write only the changed header and/or body, force-repair any body whose declared track count differs from its cached ordered membership count, and preserve the last-good snapshot when the response has an explicitly older modification date. This comparison must include the key, title, artist, album, duration, artwork, and source fields used to render playlist-only tracks without a canonical library row. Orphan deletion follows only a complete playlist inventory. Incomplete/failed fetches preserve the last-good local cache, and material library writes remain publishable when a later playlist phase fails. Initial source setup records a device-local pending marker before enablement, stays retryable across relaunch, shows the provider error, and clears that marker only after every required sync phase succeeds. Leaving Add Source cancels its structured setup attempt without clearing pending retry state. Removing the source clears its library, downloads, artwork, playlist-capability cache, library-inventory cadence state, failed-hub status, recent playlist target, and pending setup marker while preserving generic view and navigation preferences. `AppleMusicSourceProvider` owns these snapshots.
- Apple Music Add Source remains structured through authorization and subscription validation, then dismisses immediately after local enablement while coordinator-owned sync continues in the background. Source sync is single-flight across startup, bulk refresh, and explicit retry; removal cancels and drains that owned work before cleanup. Profile exposes sync progress, every preflight/provider error, and a retry action; the pending setup marker remains authoritative until every required sync phase succeeds.
- Empty or failed network results must not overwrite last-good Feed snapshots.
- Browse empty/add-source decisions are readiness-owned. `AppReadinessCoordinator` is the source of truth for bootstrap-settled, cached-library/feed-ready, no-source, and no-enabled-library states; Feed/library views must not infer those states from transient account, hub, playlist, or source arrays.
- While credentials or iCloud source restoration are unavailable or still loading, Feed and library browse surfaces must preserve or publish cached source content using cached source keys provisionally. A failed Keychain read, or an empty credential store alongside a last-good cache, must not filter cached hubs or rows.
- Plex discovery and iCloud credential reconciliation must preserve cached servers omitted from a partial resources response. A server may be removed only through an explicit account removal; temporary discovery absence must not remove its libraries from Settings or browse filtering.
- Feed uses stale-while-revalidate cadence: fetch once per app session or when the last network snapshot is at least 10 minutes old; manual pull-to-refresh bypasses the cadence. A settled source-configuration change also bypasses the cadence: preserve the visible last-good snapshot as stale, then refresh the combined enabled-source snapshot immediately or when the hidden Feed next becomes visible.
- Each enabled `MusicSourceSyncProvider` supplies normalized Feed hubs through `getHomeHubs(limit:)`, including explicit semantic kind and source/server scope; `HomeHubLoader` must not infer merge behavior from provider hub IDs or display titles. `HomeHubLoader` is the only owner that collects, merges, globally orders, and saves the combined snapshot. Search reads that snapshot and must not perform a parallel hub fetch or replace it with one provider's payload. A partial refresh retains last-good items for each failed provider while accepting successful providers' fresh items. Plex providers use inline hub metadata and skip hubs without usable music items. Apple Music supplies Recently Added from library-added albums, Recently Played from MusicKit's recently played song history (capped at Apple's 30-item request maximum), and Most Played from library song play counts; one unavailable Apple hub must not suppress the other successful Apple hubs, and recovered providers must be removed from the failed-key set.
- Recently Added, Recent Plays, and Most Played merge across every enabled source using every item returned by the requested hub count. Recently Added and Recent Plays interleave items newest-first using normalized `addedAt` and `lastViewedAt`; Most Played orders by normalized `viewCount`, then `lastViewedAt` for ties. Hub persistence retains these ranking fields and each item's provider playback key so cache reloads and partial refreshes preserve ordering and exact catalog/library routing. Feed local-cache enrichment must retain provider-actionable Apple Music items when no matching library row exists; Plex items still require an exact locally available row. When source aliases return the same physical item, keep the copy that ranks highest by that hub's ordering metadata, while preserving matching IDs from different servers, libraries, or providers. Other hubs remain within their provider-declared source/server scope. Feed hub ordering is global across the combined snapshot and must survive cached, partial, and refreshed payloads through stable merged-hub identities.
- Refreshable root screens attach `.refreshable` to the native scroll owner for every visible content state and expose `.refreshCommand` so keyboard/menu refresh invokes the active screen's same action.
- Library pull-to-refresh remains incremental. Artist refresh compares the current Plex artist payload with source-scoped cached metadata because PMS may not advance artist or section timestamps after a metadata edit. Album and track refresh remains item timestamp-filtered between authoritative reconciliations and must not skip those queries based on the library section `updatedAt`, which PMS may leave stale. Cold launch, background app refresh, and return from background require complete Plex album/track metadata comparison plus authoritative orphan inventory because WebSocket events that occurred while disconnected cannot be replayed. The same reconciliation runs at least once every 24 hours during continued foreground use. Cached rows remain visible while this work runs. The Source account detail screen exposes `Force Full Sync` for all enabled libraries in that source, bypassing Plex item timestamp shortcuts when metadata integrity is uncertain.
- Plex WebSocket library events retain the exact rating key, media type, and latest state for each changed item. `PlexWebSocketCoordinator` coalesces event bursts without discarding a distinct edit during its recent-sync cooldown; `SyncCoordinator` and `PlexMusicSourceSyncProvider` reconcile those exact items before ordinary incremental sync. Artist edits also refresh their albums and tracks, and album edits refresh their tracks, because those rows retain denormalized parent names. Additions fetch their exact parent chain. Deletions invalidate only the affected source's inventory timestamp so orphan reconciliation runs immediately without erasing the independent full-metadata cadence. A recent unchanged sync skips inventory work.
- Background refresh routes through `BackgroundRefreshCoordinator`, not transient UI view models.
- WebSocket library/update/download events accelerate refresh and sync. A physical Plex server event refreshes every enabled source with the same server identifier and library section, even when those sources belong to different Plex accounts; account identity remains part of cache ownership, not event isolation. Debounce, in-flight guards, cooldowns, polling timers, and foreground refresh remain fallback paths.
- Source cleanup is destructive and must stay outside UI view models. Run it only for an explicit account/library removal or explicit cache-clear action; an empty, loading, or unavailable credential result must never infer deletion. Explicitly removed/disabled sources clean library rows, Feed hub items, lyrics, source-scoped persistent artwork, offline targets, downloads, and pending mutations through `SourceCacheCleanupService`; cleanup also removes invalid unscoped mutation rows, and removing the final Plex library on a server removes server-scoped playlist mutations so none of them can replay if the same source key is later re-added. All-library cleanup deletes every pending or failed mutation. Durable artwork is source-scoped v2 only: `ArtworkDownloadManager` never reads, writes, or migrates unscoped entries. Background startup work deletes every pre-v2 cache entry when the v2 marker is absent, writes the marker only after a successful purge, and retries on a later launch if upgrading fails; this cleanup must not block app launch. Shared bounded Nuke rendering caches may be cleared globally because their entries are disposable. A global transient artwork reset invalidates the old Nuke pipeline before clearing its memory/disk state plus `ArtworkLoader` URL tracking and blur caches, then installs a fresh bounded pipeline so cancelled requests cannot repopulate removed-source assets.
- Explicit removal invalidates the provider registration before destructive cleanup. Every source-owned persistence path, including sync, Feed snapshots, playlist refresh/mutation reconciliation, playlist creation persistence, pending mutations, lyrics, and detached durable artwork writes, must hold the shared source lease through its final write. Plex library leases also join their server fence so server cleanup drains every child-library write. Cleanup rejects new leases, drains existing library and server-scoped playlist leases, and rechecks restoration before and after destructive cleanup. A source restored during cleanup is released and resynced; server restoration resyncs every enabled library on that server. If the source remains removed, cleanup discards only that source's pending artwork invalidations, performs one final purge, and only then publishes `sourceCleanupDidComplete`; Library, Feed, Search, and Playlists consume that completion to reload the authoritative post-purge state. Provider registration and source-configuration generations must reject an older provider even when the user removes and re-adds the same composite key, while an unrelated source refresh must preserve current work for unchanged source keys. Cleanup failure must not publish completion or dismiss a removal surface as successful; keep a visible retry/error path.
- Artwork metadata invalidation and orphan cleanup carry the exact source key. A changed or removed rating key in one source must not stale or delete another source's matching key, and normal library/playlist orphan removal must delete that orphan's durable source-scoped artwork so cache size does not grow indefinitely with catalog churn.
- Sync should pre-cache detail-grade album, artist, and playlist artwork before users navigate into artwork-backed detail surfaces. Existing persistent artwork should only skip sync caching when it satisfies the full-size detail requirement; undersized thumbnails remain fallback files and should be replaced during sync while the server is available.
- Library sync should persist Plex EP and Single format classification so cached artist albums are grouped correctly before the artist detail supplement finishes. A failed format query must preserve last-good classification.
- Server playlist freshness and inventory state should be durable. `SyncCursorRepository` owns `CDSyncCursor` rows for server playlist sync. New playlist sync paths should prefer scoped cursor state over scattered `UserDefaults`; legacy defaults may remain only as migration/backward-compatibility fallbacks.
- Incremental and full playlist cursors must capture the Plex query start boundary and commit it only after the sync succeeds. Do not advance a cursor to completion time, which can skip server changes made while the sync is running; durable cursor writes must also be monotonic when refreshes overlap.
- Incremental playlist sync should fetch added/updated playlists each run, but full playlist inventory for orphan removal should run only after playlist changes, first/full sync, or a periodic cleanup window. Startup sync must avoid repeating inventory-only orphan checks when Plex reports no playlist changes and a recent cleanup exists.
- Full/manual playlist sync should refresh playlist inventory metadata, then fetch playlist track lists only for new, server-updated, or locally bodyless playlists where the server reports tracks. Incremental sync must not repeatedly repair unchanged playlist bodies: Plex's advertised track count can permanently exceed the body endpoint because smart, unavailable, or inaccessible items are omitted. A cached membership counts as body content even when Plex omits its playlist item identifier or its library track is unavailable. Keep the full/manual bodyless repair path so destructive cache clears or cross-device source changes can rebuild playlist bodies without forcing every unchanged playlist to re-download on every launch.
- Playlist fallback artwork persistence includes the artwork-owning source key, which may differ from a server-scoped playlist key. Playlist browse and detail must use that persisted fallback when no composite exists; legacy loaded-track fallback remains a recovery path. Album-backed fallbacks reuse the album artwork identity rather than creating a playlist duplicate. Legacy fallback backfill must use bounded work and late track relinking must repair a previously unresolved fallback rather than leaving a permanent placeholder.
- Successful and offline-queued playlist metadata mutations must update the source-scoped local playlist row before publishing refresh completion. Open details, lists, and sidebars should retain the optimistic value until Plex reconciliation supplies authoritative metadata; a stale pre-mutation cache reload must not overwrite it.
- If Plex returns source artwork below the requested detail size, the successful detail-size fetch attempt should be recorded with the persistent artwork identity so future syncs do not re-download the same server-limited image until the source path or modified date changes.
- Siri media index, media context refresh, and automatic startup sync are freshness work where relevant and must stay source-scoped. Defer this work while the device is known offline, coalesce concurrent Spotlight/Siri index refresh requests, keep shared-container index file I/O off the main actor, and route startup sync plus Spotlight/Siri indexing through foreground idle budgeting so launch, scrolling, navigation, Now Playing gestures, share sheets, and audio-critical windows remain responsive on constrained devices.
- macOS builds without the configured iCloud container entitlement must disable CloudKit profile transport and report it as unavailable instead of crashing during dependency bootstrap. Properly entitled production and development builds, plus iOS-family builds whose entitlements are validated at installation, must retain normal CloudKit behavior.
- A build with unavailable iCloud transport must settle first-connect bootstrap immediately; it must not spend the launch retry budget waiting for credentials or profile data that the build cannot access.
- macOS Keychain hydration gets a one-second presentation deadline. If the system read is still blocked, cached content becomes eligible immediately; a later successful result may still restore live sources.
- Constrained legacy devices such as iPhone 6s/iPad Air 2 should use a longer foreground idle delay before nonessential work. Navigation events from `NavigationCoordinator` must mark the `ForegroundWorkScheduler` as navigating so automatic startup sync cannot begin under a tab change, push, pop, or external route transition.
- While the device thermal state is Serious or Critical, `ForegroundWorkScheduler` must defer nonessential analysis, healing, indexing, background artwork retries, startup sync, log export, and derived download-progress recomputation until the device recovers. Visible artwork recovery and user-requested playback or download transfers remain eligible. `PowerStateMonitor` should log thermal transitions so performance sessions can attribute the gate without polling additional system state.

## Owners

- `SyncCoordinator` is the sync facade and owns actual sync policy.
- `AppleMusicSourceProvider` owns authenticated MusicKit data requests plus cached Apple library/playlist snapshots on supported iOS devices.
- `NetworkLifecycleController` owns app-foreground and network-transition refresh/invalidation planning.
- `PeriodicSyncController` owns foreground timer scheduling and WebSocket-aware polling interval policy.
- `BackgroundRefreshCoordinator` owns app-refresh and foreground freshness sequencing.
- `HomeHubLoader` owns Feed snapshot loading used by Feed and background refresh paths.
- `AppReadinessCoordinator` owns launch/source/cache readiness snapshots consumed by browse surfaces.
- `ForegroundWorkScheduler` owns idle gating for nonessential refresh-adjacent indexing and retry work.
- `SourceCacheCleanupService` owns destructive source/all-library cache eviction.
- `ArtworkDownloadManager` owns source-scoped durable artwork identity and the one-time pre-v2 cache purge.
- `SyncCursorRepository` owns durable source-library and server-playlist cursor/freshness state.
- `PlexWebSocketCoordinator` owns coalesced WebSocket event routing into sync/download/health flows.

## Implementation Hooks

- Use `HomeHubLoader` or `BackgroundRefreshCoordinator` for Feed refresh. Do not create `HomeViewModel` only to refresh background data.
- Route Hub replacement, freshness, and deletion writes through `HubRepository`'s serial write context so overlapping refreshes cannot leave duplicate snapshot graphs.
- Keep cached rows visible during refresh after a screen has shown content; mark stale/loading locally rather than blanking the surface.
- Feed, playlist, artist, album, track, genre, and library browse refreshes should publish committed snapshots atomically. Degraded empty/partial reloads should preserve the current visible snapshot until bootstrap is settled and the repository confirms the empty state is authoritative.
- `LibraryViewModel` loads are single-flight and generation-scoped. Triggers during an active load coalesce into one follow-up pass using the latest source configuration; an older pass must not overwrite or finalize the newer source-filtered browse snapshot.
- Playlist root, search, Feed, and Pinned lookups fetch persisted headers and fallback artwork without realizing `playlistTracks`; only playlist detail, body, and sync-state operations fetch memberships. Legacy fallback-artwork repair runs from root/reference header loads and remains bounded to 20 one-row membership lookups per pass.
- Library browse must not realize per-album track relationships to calculate counts. Map counts from the already-fetched source-scoped track inventory in one pass; sync should persist an authoritative provider or inventory-derived count when available, and a missing provider count must not overwrite a known cached count.
- Genre browse rows are normalized display categories keyed by title and must be backed by at least one visible album genre match. Duplicate genre titles across visible enabled sources should merge for display, and genre detail should resolve albums from cached album genre metadata across those visible sources without requiring a live Plex refetch.
- `AccountManager.sourceConfigurationPublisher` is the deduplicated provider-neutral source snapshot for shared consumers. Authority is provider-local: library, Playlists, Search, Feed, Favorites, and restored playback state enforce enabled sources for a settled provider (including device-local Apple Music) and may preserve valid unresolved providers provisionally. Missing or malformed source ownership is invalid and never gains an inferred owner. An authoritative empty credential snapshot alone still does not prove deletion of last-good browse data; explicit source cleanup removes those rows. A transport-only Plex connection change must not publish a source change.
- Mood browse rows are display categories keyed by normalized title. Plex mood keys are library-local, so merge duplicate mood titles across sources for display and carry per-source mood keys when available. Mood detail pages should use the cached per-source key first and only refetch/resolve the current library's mood key when cached metadata is missing or stale.
- Keep WebSocket event handling idempotent and safe to miss.
- Use `SyncCursorRepository` for scoped sync freshness decisions. Plex library and server playlist inventory reconciliation should record full/inventory/incremental completion there and clear the matching cursor when scoped rows are purged.
- `SyncCoordinator` owns full-size persistent artwork pre-caching through `cacheAlbumArtwork`, `cacheArtistArtwork`, and `cachePlaylistArtwork`; detail views should treat sync output as the durable cache source and use visible loading only as a recovery path.
- `MusicSourceAccountDetailView` routes `Force Full Sync` through `MusicSourceAccountDetailViewModel.syncEnabledLibraries()` and the existing source-scoped `SyncCoordinator.sync(sources:)` full-sync path.
- `MutationCoordinator` owns durable optimistic playlist rename persistence through `PlaylistRepository.updatePlaylistTitle`; `PlaylistDetailViewModel` must not immediately replace the optimistic title from a stale cache snapshot.
- `ArtworkIdentity.requestedPixelDimension` records the largest persistent artwork request already attempted for the current source identity; `ArtworkDownloadManager.localArtworkExists` uses it to distinguish stale thumbnails from server-limited detail responses.

## Verification

- Add or update freshness tests for Feed cadence, last-good preservation, manual refresh bypass, and background refresh behavior.
- Use simulator validation for pull-to-refresh, refresh commands, cached-content stability, and source enable/disable flows.
- Use performance gates when changing Feed launch/refresh or high-frequency WebSocket publication behavior.
