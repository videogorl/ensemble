# UI Platform Policy

Load this reference for platform navigation, native UI ownership, persistent surfaces, cached-content stability, detail surfaces, utility screens, menu/swipe actions, visual surfaces, or watch behavior.

## Policies

- Root shells own platform navigation: tab shell on iPhone, split/sidebar shell on iPadOS and macOS where supported.
- The root sidebar on iPadOS and macOS should use a native `NavigationSplitView` column width range rather than a fixed min/ideal/max width, so pointer/window users can resize the sidebar while the app still provides bounded defaults.
- Large-screen browse splits that collapse to a single inner pane must keep a visible navigation control for returning from the selected detail to the browse list.
- iPhone root profile toolbar chrome is owned by `MainTabView` at each visible tab root-content wrapper and the root More wrapper, not by individual screens. On iOS 16+, it stays mounted at that root owner instead of toggling from navigation path emptiness; iOS 15 may path-gate the fallback item to prevent inherited toolbar leakage. Root browse toolbar items follow the same rule: `AlbumsView` keeps its sort/filter toolbar mounted on iOS 16+ so detail navigation cannot disturb the album scroll position, while iOS 15 retains path gating. Root actions must stay absent from pushed destinations and hidden-tab drill-ins.
- Navigation coordinators are scene/window-scoped. Do not route user-driven navigation through shared singleton state that mirrors iPad/macOS windows.
- Automation start surfaces must use the same scene-local navigation paths as visible controls. On sidebar shells, `settings` is an alias for the native Profile presentation because settings are not a sidebar row; `profile` and `profile-storage` use that same presentation path.
- Static iPadOS/macOS sidebar destinations must expose an accessibility activation action that routes through the same `MainTabView.selectSidebar` path as native list selection, preserving navigation resets, user-journey logging, and automation behavior.
- Feed cards and hub headers use scene-local `NavigationCoordinator` typed routes, not inline destination closures tied to mutable hub arrays. A Feed refresh must not pop a pushed album, artist, playlist, or hub-header destination.
- Feed exposes its hub-ordering Edit toolbar item only when enabled libraries provide hubs to edit; empty Feed states must not reserve invisible toolbar space for it.
- Media browse and relationship links use scene-local `NavigationCoordinator` typed routes without hard-coding the owning tab. Album, artist, playlist, pinned, search, related-item, and detail subtitle links should append to the currently active stack so hidden More-tab routes and iOS 15 fallback stacks can continue drilling into nested details. Route-owned controls should mutate the coordinator path directly instead of relying on nested `NavigationLink(value:)` resolution from pushed destinations; More-tab drill-ins must keep tappable rows and cards after the first push.
- On iOS 18+, Albums browse routes to concrete album details use SwiftUI's native zoom navigation transition, sourced from the tapped album artwork with a namespace owned by the existing root stack. Earlier iOS versions keep the standard system push, and no secondary navigation container or custom transition layer should be introduced. `MainTabView`, `SidebarView`, `NavigationDestinationFactory`, `AlbumsView`, `AlbumGrid`, and `AlbumCard` own this handoff.
- Keep native platform owners for behavior SwiftUI does not expose: native track tables, AirPlay picker, Metal aurora, global toast window, native share/menu hosts, iOS 15 tab/mini-player bridges, and macOS menu/window behavior.
- The root mini player should render as soon as root geometry exists and show its empty state when no current track is available; it must not wait for restored Now Playing state, library refresh, or playback projection updates before becoming visible. Root geometry already ends at the safe-area boundary. When a tab bar is present, convert its measured window-bottom clearance into that root coordinate space by subtracting the bottom safe-area inset, then add the shared additional padding; without a tab bar, apply no additional root lift. This preserves the effective safe-area inset without counting it twice across iOS 15 and newer. The floating mini player owns no additional transparent bottom padding. On iOS and iPadOS, the root mini player should hide while the software keyboard is visible. Root chrome owners should suppress the mini-player overlay and its reserved clearance instead of letting the mini player ride above the keyboard, then restore the mini player after keyboard dismissal. On iPadOS, the mini player should stay in the `RootSceneLayerHost` overlay so it shares the root view's rotation and safe-area coordinate space. iPadOS placement should use root-space coordinates centered on the active content viewport: root bounds when the sidebar is closed, and root bounds minus the frozen visible leading sidebar metric when the sidebar is open. Destination views and pushed detail content must not influence root mini-player placement. Transient absence of a sidebar preference during navigation rendering is not a sidebar-close signal; the split owner's explicit sidebar registration should switch between the root viewport and sidebar-adjusted content viewport. Only sidebar visibility/width, root rotation/size, keyboard suppression, and Now Playing presentation should move or hide the persistent shell. On iOS 26+, the persistent root mini-player shell should use native Liquid Glass without a shared glass-effect identity that lets the system animate the shell during unrelated navigation transitions.
- Viewport Now Playing on iPadOS and macOS is modal: while `RootSceneLayerHost` presents it, covered root content must be excluded from accessibility and hit testing. Restore both when Now Playing closes. Native iPhone sheet behavior remains system-owned.
- Aurora surfaces should mount immediately when the aurora setting is enabled and draw a deterministic idle frame before restored playback state or live frequency bands arrive. Root, Now Playing, and Stage Flow aurora hosts should not render a blank Metal/Canvas surface while playback, settings defaults, or analyzer consumers are hydrating; live bands should replace the idle frame when playback analysis starts.
- Large-screen root aurora uses the existing single `.rootBackdrop` surface owned by `RootSceneLayerHost`. Do not add duplicate root aurora renderers or sidebar-specific shield geometry unless a current visual repro justifies revisiting the model.
- Treat new safe-area compensation, delayed layout tasks, custom scroll detectors, root-chrome mutation, toolbar proxies, or broad UIKit/AppKit appearance changes as suspect until a current simulator/macOS repro proves native behavior is broken. Detail leaf views must not hide/show the platform navigation bar to mask transition artifacts; keep toolbar visibility and material behavior declarative through the shared toolbar/detail-surface owners.
- Persistent list/detail surfaces should observe focused projections or local state snapshots, not broad high-frequency singleton objects.
- Library browse screens that have already displayed cached content should not publish transient empty lists or swap to blank loading states during refresh. Root library tabs may seed their visible browse snapshots synchronously from cached published collections while the debounced sort/filter pipelines catch up; do not show loading solely because a debounced display projection has not published yet.
- Shared media menu and swipe action policy lives in `MediaMenuCatalog` and native table/menu renderers. Parent views should add only local handlers.
- Track, album, artist, playlist, and merged-playlist menus expose `Share Ensemble Link…` in addition to existing streaming-link and audio-file actions. These versioned `https://ensemble.videogorl.me/media/v1/...` Universal Links contain portable descriptive metadata, never Plex credentials or source IDs, and resolve only against the recipient's enabled cached libraries. Legacy `ensemble://media/v1/...` links remain readable. Universal-link browsing activities and custom-scheme URLs must enter the same permalink handler. Opening a link navigates without starting playback; song links open the matched album, same-named playlists match case-insensitively and use `DisplayPlaylist` merging, and unresolved links route to Search with non-destructive feedback. `EnsemblePermalink`, `EnsemblePermalinkResolver`, `NavigationCoordinator`, `SongPermalinkLoader`, and `ShareActions` own this flow.
- Shared audio files must be complete original-quality files: validate streamed exports against Plex file metadata or the response length before presentation, and keep system-temporary files alive after the activity callback so Files, Final Cut Pro, and other receiving apps can finish reading them. `ShareService`, `ShareActions`, and `ShareSheetPresenter` own this flow.
- iPhone and iPad native track-list rows expose configured track swipe actions from the shared swipe layout; do not gate `MediaTrackList` swipe configurations to phone idiom only.
- Library track, album, and single-playlist context menus expose `Get Info…` through `MediaMenuCatalog`. iOS/iPadOS present it as a sheet; macOS presents one reusable native window whose content updates for the latest selected item. The panel shows file/library metadata only and must not include live Now Playing rows such as current playback file, queue quality, lyrics, network, or active connection status. Track and album file sections may show original Plex media paths, but those paths must be hidden when Demo Mode is enabled.
- The macOS Dock menu is an AppKit bridge owned by the app target. It shows pinned albums/artists/playlists first, then Now Playing controls, and dispatches to existing navigation, playback, and mutation owners instead of creating alternate UI business logic.
- Detail screens with artwork-backed washes should use shared detail surface and toolbar-bleed owners so media details, download details, and artist details do not drift. Media detail artwork should use `ArtworkImageResolver` as the single cache-first image-loading owner for the header and backdrop: reserve a stable artwork frame, seed from already cached artwork when available, then replace with the resolved image without an intermediate nil/placeholder frame. Artwork blur must be pre-rendered and cached before display, not applied as live SwiftUI `.blur` to large layers or generated by navigation/layout views. The in-memory blurred-artwork cache must remain byte- and count-bounded, reuse one Core Image context, and clear on memory warnings; persistent blur files provide recovery after memory eviction. Visible destination backdrops and the Feed profile-image backdrop should use the visible artwork path so the wash is not delayed behind idle-only background scheduling; background/bulk retries may still be idle-gated. Remounted root/detail backdrops should seed synchronously from their stable blur cache key when available, so back navigation does not repaint through an unwashed placeholder while `.task` reloads run. If a detail backdrop render is not available at navigation time, the generated/cached result should fade in when it arrives; if the stable blur render already exists, it should be visible immediately with no artificial reveal. Sync should pre-cache detail-grade album/artist/playlist artwork before detail navigation needs it; visible detail artwork loading is a recovery path, not the primary durable cache path. Persistent artwork files that are too small for a visible detail request should be treated as offline fallback only: online detail loads should fetch and replace them, and small thumbnail requests should not seed durable album/artist/playlist artwork cache. If a visible network artwork URL resolves but the image request fails, `ArtworkImageResolver` should retry persistent local artwork before showing a placeholder. Playlist browse artwork and detail headers should use the playlist composite first, then fall back to the first loaded track artwork when the composite is unavailable. Album-backed fallbacks reuse the album's persistent asset rather than creating a playlist-owned duplicate. Backdrops should keep the previous resolved artwork wash only for the same artwork continuity identity while the next detail artwork is unavailable, then cross-fade the wash only when the new artwork arrives. Artist detail hero continuity is identity-scoped: previous artwork may be reused only for the same `artist.sourceScopedID` or an explicitly shared artwork identity. Different artists should render reserved geometry or a low-resolution seed, never the previous artist's image. The foreground artist hero image should dissolve with an alpha mask into the shared cached blurred artwork backdrop; do not paint an opaque surface-color gradient over the hero fade. Compact/collapsed artist detail keeps an Apple Music-style foreground hero: the visible container is 1:1 at rest, normal scrolling down into content must not resize or reframe the image, and only positive top rubber-band pull may expand the foreground image height while pinning it upward so the stretched area remains filled. Do not drive compact artist hero sizing from safe-area compensation, notch/dynamic-island thresholds, or transition-captured resting baselines; use the live top overscroll from `ArtistDetailView.heroBanner(containerWidth:)`, with `MediaDetailSurface` and `artworkBackedToolbarBleed()` owning the surrounding wash and toolbar bleed. Content should still render immediately without artificial reveal delays.
- If a detail-size artwork fetch succeeds but Plex returns a smaller source image, detail views should use that cached image rather than causing sync or visible recovery paths to repeatedly request the same server-limited artwork.
- The root mini player should use a system-color/material background rather than artwork-backed blur because it remains visible under most phone surfaces. Now Playing and detail surfaces may keep artwork mood, but all artwork blur must flow through the shared cached pre-renderer.
- Media detail screens should render cached header/list content immediately. User-driven navigation from a surface that already has an `Album`, `Artist`, or `Playlist` model, including resolved sidebar pins, should push the concrete detail view directly instead of routing through an ID-only loader. Do not hide cached detail content behind artificial reveal delays, opacity fades, or supplemental metadata loads; richer metadata may fill in after the base detail surface is interactive. Artist detail separates likely full albums from Singles & EPs. Plex exposes music releases as `type=album` and can omit single-track releases from `/library/metadata/{artist}/children`, so `PlexMusicSourceSyncProvider.getArtistAlbums` should prefer the section-level `artist.title` album query when the source library key is available. Plex release grouping is exposed through the music library `format` filter (`/library/sections/{sectionKey}/format?type=9`) and album detail `Format` tags such as Album, EP, and Single; use those values as the sole artist release-section classifier. Cached albums should remain visible first, with API supplement/fallback behavior preserved in `ArtistDetailViewModel` and `MergedArtistDetailViewModel`.
- Playlist detail navigation should not load or map full track relationships before rendering the detail surface. If tracks or derived filters are still loading, show that state inside the track list/footer and reserve stable genre-chip header space so the header and toolbar remain stable.
- Loading, empty, and error states should use shared state scaffolds rather than rebuilding decision trees per screen.
- The Lyrics panel transport should show the same delayed loading indicator as the Controls panel while playback is loading or buffering. The panel may expose chord streams with the `music.pages` control beside instrumental mode when the current track has a chord stream. Chord rendering is fully monospace, treats whitespace as source data, colors chord symbols with the selected app accent color, renders chord rows paired above lyric rows, shows `🎵🎵🎵` as the lyric placeholder for chord-only rows, wraps chord and lyric text on shared character-column boundaries, does not apply progressive lyric blur, and highlights the current plus next timed row so musicians can prepare for upcoming changes. Timed chord parsing treats timestamped rows as lyric rows and the immediately preceding untimestamped physical row as that timestamp's chord row. Untimed chord streams use simple physical row pairs: chord row, then lyric row. Paired wrapping is applied within each visual lyric line so manual returns do not count as chord columns.
- Watch is an independent lightweight Plex client plus optional iPhone remote, not a full `EnsembleCore`/`EnsembleUI` client. Downloads are outside the current standalone watch scope.
- Watch account bootstrap reads the iPhone app's synchronizable Plex credentials through their shared Keychain access group; Plex Link remains the fallback when no synced credentials exist.
- Watch server discovery retains the endpoint that successfully returned Plex library sections so subsequent catalog, artwork, and playback requests begin from the verified connection rather than the original candidate. `EnsemblePlexDiscoveryService` owns this handoff.
- Watch Pins contains only media referenced by the user's synchronized pin preferences. An empty pin list remains empty; Recently Added content stays in its own browse surface.
- Watch Pins reads the iPhone app's shared KVS store and refreshes when iCloud delivers external preference changes. `WatchCloudPreferenceStore`, `WatchExperienceModel`, and `WatchRootView` own this flow.
- Watch Albums keep every selected-library item reachable through a lazy vertical scroll stack. Each full-height card contains only album artwork and title, uses an interactive bottom-hinged scroll transition to evoke flipping through a physical album stack, and opens album detail when tapped; album actions remain in detail. The system owns Digital Crown scrolling and page settling, with no page indicator or custom drag recognizer. Watch Playlists fetches each selected Plex server's server-scoped playlist inventory once, then merges same-named playlists with matching smart status using the shared iOS identity and stable ordering rules. Watch Artists contains only artists referenced as an album artist by at least one selected-library album. Albums, Artists, and Playlists are globally title-sorted across selected sources using the iOS leading-article rules (ignoring `The`, `A`, and `An`); Artists and Playlists remain grouped into alphabetical sections and expose the system list index on watchOS 26 and later. Recently Added preserves recency order and remains capped at 24 items. `EnsemblePlexCatalogService`, `WatchExperienceModel`, `WatchPlaylistGroup`, `WatchCategoryView`, and `WatchAlbumBrowseCard` own the browse catalog.
- Watch album and playlist details use the system vertical-page `TabView`: a fixed artwork page with Play, title, and More in the system bottom toolbar, followed by a native track `List`, so toolbar sizing, the Digital Crown, page transition, and page indicator remain system-owned. Merged playlist tracks round-robin across constituents while preserving each track's source for playback; a failed source leaves healthy source results usable. The hero's More control uses the same scoped Play, Shuffle, and Pin/Unpin actions as browse rows, and merged playlist pin changes apply to every constituent. Album track sections preserve Plex disc and track numbering without row artwork; playlist track rows show track artwork and artist metadata. `WatchTrackCollectionDetailView`, `WatchMediaActionTarget`, `WatchExperienceModel`, and `EnsembleTrack` own this presentation.
- Every Watch Play or Shuffle action, along with detail-track taps, starts its scoped queue and pushes the fixed, non-scrolling Now Playing view. It has no title, uses a pre-rendered artwork wash behind artwork/title/artist, keeps Close and overflow in the system top toolbar, and keeps Previous, Play/Pause, and Next in the system bottom toolbar. The Play/Pause button surrounds its icon with progress from the active local or iPhone playback clock. Now Playing content must remain above the native transport toolbar on compact Watch displays. The overflow owns local/iPhone target selection; the Digital Crown owns local volume. `WatchRootView`, `WatchNowPlayingView`, `WatchArtworkLoader`, and `WatchPlaybackController` own this presentation.
- Watch renders its persisted catalog immediately and keeps it interactive during credential checks, server discovery, manual refresh, and recoverable failures. Automatic launch refresh reuses snapshots younger than 10 minutes; manual refresh bypasses that cadence without replacing cached UI. `WatchExperienceModel` owns this stale-while-revalidate behavior.

## Owners

- `RootView`, `RootSceneLayerHost`, `MainTabView`, and `SidebarView` own root navigation, root chrome, root aurora layering, auxiliary presentation, and scene/window coordinator injection.
- `NavigationCoordinator` owns typed destinations, pending navigation, active auxiliary presentation, and scene-local routing.
- `EnsemblePlatformFeaturePolicy` owns shared platform feature availability.
- `MediaTrackList`, `SongsTrackListHost`, native menu/share hosts, AirPlay, Metal, and toast bridges own platform-specific behavior.
- `MediaMenuCatalog`, `NativeMediaTableActionBuilder`, and menu renderers own shared action availability and ordering.
- `EnsembleScaffold`, `MediaDetailSurface`, `ArtworkDetailBackground`, `ArtworkImageResolver`, and design tokens own shared UI structure, artwork loading, and visual policy.

## Implementation Hooks

- Load `ui-conventions` for detailed SwiftUI/component implementation rules after loading this policy.
- Keep search, tab, toolbar, root aurora, and mini-player chrome ownership at the root or platform owner; avoid leaf-level fixes unless the leaf owns the real platform behavior. `RootChromeFrameRegistrationView`, `RootChromeResolvedFrameRegistrationView`, `RootSidebarChromeRegistrationView`, and `RootChromeLayoutResolver` own mini-player placement geometry.
- Keep compact iPhone fallbacks separate from large-screen split behavior.
- Use shared scaffolds, labels, icons, materials, and track-list metrics instead of local duplicates.
- Mark mini-player, Now Playing panel, carousel, scrubber, share-sheet, and route transitions as foreground interactions through `ForegroundWorkScheduler` so nonessential work does not start during visible gestures or native presentations.
- `ForegroundWorkScheduler` waits for nonessential foreground work must return denied when the app leaves foreground or the waiting task is cancelled; artwork retries, indexing, and analysis must not remain parked on the main actor during process exit.
- Use native commands and keyboard shortcuts where available; do not install app-wide input monitors for ordinary shortcuts.

## Verification

- Use simulator/macOS validation for navigation, modal presentation, keyboard, toolbar, safe-area, split-view, or root chrome changes.
- Search root chrome should remain mounted through the native tab handoff and collapse only after the outgoing Search frame is no longer visible, so leaving Search does not relayout the outgoing tab before the destination tab appears.
- Use screenshot or accessibility evidence for substantial visible UI behavior changes.
- Validate Lyrics chord UI changes for button visibility, monospace alignment, paired wrapping, chord-only timed rows, and current-plus-next highlighting.
- Use performance checks when changing persistent root/list observation, Feed refresh UI, Downloads queue UI, or high-frequency visual surfaces.
